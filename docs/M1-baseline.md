## 模块职责与接入约定

| 模块 | 现有入口及后续职责 |
|---|---|
| 应用装配 | `src/app/App.tsx` 管身份入口；`Workspace.tsx` 管三舱、导航、共享运行时和对话返回。以后只挂载领域页面，不继续堆逐组／餐食表单 |
| 训练页面（待建） | `src/app/training/` 管空白训练、动作/setup 选择、半填组、暂停／结束确认、本次结果；保留领域特有确认规则 |
| 饮食页面（待建） | `src/app/nutrition/` 管餐食编辑、营养／份量、描述草稿和完整度；历史快照不随引用更新 |
| 共享界面能力 | `use-draft.ts`、`workspace-state.ts`、`ConfirmDialog.tsx`、`NumericText.tsx` 复用持久草稿、命令构造、确认与数字排版；共享组件有实际第二个用途再抽取 |
| 本机与队列 | `src/client/local-database.ts`、`command-queue.ts`、`synchronizer.ts` 统一存储、依赖、回执、重试与增量同步；每个 owner 一个工作区运行时 |
| 领域契约 | `src/domain/manual-commands.ts` 负责类型化命令到 HTTP 的映射及版本来源；training／nutrition 模块负责输入与纯规则，页面不自算另一套事实 |
| 服务端 | `training-api.ts`／`nutrition-api.ts` 管协议与鉴权上下文；领域服务经 `commands.ts` 提交；成功回执后才显示已同步 |
| 目录与数据库 | `db/schema.ts` 与追加 SQL；后续目录保存 stable ID、版本、三语标签、来源和审核记录；目录变更同时核对同步指纹与历史快照 |

共享草稿目前只在称重路径完成验证。训练接入时不能直接照搬固定的 weight-form ID，也不能假设通用 hook 已保存组的根／子版本；领域页面需提供自己的草稿身份与 baseRefs，并验证切换训练不会串入上一场表单。

新增命令沿用 observed revision 或前序 receipt 版本绑定；组和动作变更同时校验 session 根版本与子记录版本。连续提交共享前序依赖，不能每次重新生成意图再盲重试。结束训练必须区分本机待同步与服务端已完成。

草稿与事实分开保存；切语言、对话往返和刷新不能把旧表单覆盖最新事实。新增目录字段或命令类型时，要覆盖旧数据／已排队命令的读取兼容、同步投影和升级测试，不能只改数据库。
