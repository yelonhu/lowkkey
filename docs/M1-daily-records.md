# M1 按天记录与自动保存

本批将训练改为“这一天练了什么”，体重改为“这一天是多少”。训练、体重与公共自动同步已实施；整个 M1 仍未验收。饮食、AI、完整离线应用壳没有扩展。规范为 SPEC v1.1.6。

## 五分钟试用

启动 `./scripts/run dev`，打开 [本地预览](http://127.0.0.1:5173/today)，沿用本地虚构身份与已有记录。

1. 点击训练卡，直接添加“杠铃平板卧推”。填写重量与次数，在重量／次数／RPE之间切换不会入账；点击标题或“加一组”后自动保存。无需开始或结束。
2. 再加一组，只填重量；切到另一日期或打开对话后返回。半填内容仍是草稿，已记录组数不增加。填好次数并离行，再次进入该日期仍可修改。
3. 点击体重卡，再点击大数字或“—”。填写体重与单位，离开编辑区后自动保存。再次修改更新当天同一条记录；切显示单位不改原始事实。
4. 查看以所选日期结束的28天点图与七日均值。无当天读数显示“—”；数据不足不伪造均值。更多菜单提供测量状态与明确删除，清空数字不删除记录。
5. 在已经打开的页面断网，修改后观察“已存本机”；恢复网络后自动入账，无需刷新。新体重同步成功后可在10秒内撤销；发生冲突时就近核对。

异常体重需要确认。日期固定在正在编辑的当天，跨午夜不会搬移草稿。直接从应用根路径重开回三舱首页；带日期的链接和刷新保留该日期。旧训练链接自动进入对应日期。

## 实现与数据保护

- 首个有效组、必要的 `recorded` 日容器与动作快照原子入账；每人每天至多一个这种容器。只选动作和空行留在本机，不产生实际组。新增组默认实际时间未知，写入时间另记。
- 旧根与子项 ID、快照、时间和审计保留；旧状态继续兼容，日页面按日期聚合，统计依据实际组。删除最后一组允许当天为空。
- 体重每日接口首建或带版本更新，并发首写只有一个成功；旧主要值作为当天读数。旧副记录保留在兼容历史中，新图表不使用，删除和新接口撤销不补选。
- 草稿立即进入本机持久化队列，组行与体重数字／单位分别作为保存区。离区、日期／页面切换、对话和加组提交有效修改；后台与意外刷新只留草稿。无变化不重复入账。
- 本机命令与对应草稿版本原子消费；慢存储期间继续输入有独立令牌保护。连续编辑依赖前次回执，不猜版本。删除确认期间出现远端修改也会冲突，需重新核对或放弃。
- 本机保存后即时显示，服务端回执及账本批次都应用后才短暂显示“已同步”。只读拉取安静运行；暂时失败指数退避，最高30秒，恢复网络／前台／新命令自动处理；未知回执先查询，重试使用原幂等键。
- 身份失效暂停；冲突和不可重试错误停止对应写入。未填 RPE、组类型与测量状态保持未知，不补成估计事实。
- 追加 `0009_daily_records.sql`、Drizzle schema 与元数据，未重写旧迁移、替换资源身份或重置本地数据。

修复记录：

- 快速切语言时旧回执可能覆盖最新选择：偏好按版本串联，未确认的最新选择优先展示。
- 异步恢复期间点击体重入口可能被旧草稿状态抢回：恢复完成后才开放编辑，恢复的输入不自动聚焦。
- 无变化输入清理草稿时仍可能碰上较新编辑：删除采用草稿版本比对，不清除新值。
- 删除失败后缺少对应行操作：补核对／放弃入口，确认期间的远端修改不能自动覆盖。
- 三语测试共享日期污染历史窗口、丢失回执样例与称重样例共用日期：分离日期，不放宽唯一性或原值断言。
- 显示单位用例把上一轮空闲同步状态当成新偏好已提交：改为等待该偏好的实际服务端值。
- 对比截图禁用过渡采样，避免截到淡入中间态。过程失败报告保留为 `e2e-101-pass-one-fixture-race.json`。
