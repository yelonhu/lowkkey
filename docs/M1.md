## 已验证的基础行为

- 迁移 `0000`–`0005` 已在真实兼容本地 D1 运行时应用并验证。M0→M1 升级保留成员、档案、邀请；唯一性、外键、重复迁移和 batch 失败回滚有测试。已应用迁移不可重写；M1.1 没有新增迁移、修改依赖锁文件或改写 M0 证据。
- 服务端 `AuthContext` 由已验证身份派生，不接收客户端 owner。开发身份只在 serve/test 载入，固定虚构成员不允许请求选择；正式 build 扫描测试身份和敏感配置。
- 领域命令同事务写事实、版本、回执、审计与可信事件。人工把训练8次改为5次只生成一个批次；回执重放不重复提交，旧撤销不能覆盖后续修改。
- 体重110 lb 单次换算并保留原值，同日最多一条主要记录，删除后事务性补选。趋势不补零；七日均值至少3个实际测量日、相邻非重叠周窗口各至少4日。
- 训练含杆负重不再加杆，单侧不乘二，自重/未知 RPE 不变零；未指定器械或含义时不冒充可比较。计划和目标快照不可变，复制训练不复制已完成组，删除/恢复受训练根版本保护。
- 饮食使用原始十进制 basis 一次缩放。未知营养保持 null，标签 kcal 保留；配方/常用餐冻结来源，未确认草稿不入账并影响完整度提示。照片表存在不等于上传/下载已完成。
- 三种 `ArtifactView` 在一致截止版本投影，合计覆盖全部有效记录，列表预览不截断合计；unknown 与估算来源明确，跨用户选择被拒绝。
- 增量同步保留提交时的值、墓碑、计划选择和配方历史。owner、restore epoch、目录指纹、过期游标、批次缺口与快照跨页变化均有保护；重建保留独立草稿。
- IndexedDB 的实体和 cursor 原子提交，半份快照不可见。原始输入、返回位置与正式事实分开；存储失败回滚、多标签命令 CAS、命令依赖及回执丢失恢复有真实 Chromium 测试。
- 队列成功回执后才显示已同步。当前称重已接入在线保存、已打开页面离线暂存、重连和显式冲突处理；这不等于完整 SYN/VAL-STATE 已通过。
