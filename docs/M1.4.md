状态：本地自动化验收通过，交付产品负责人审阅。第0批基线为 `m1-engineering-baseline`，本批在 `codex/m1-training-quick` 上交付。整个 M1 尚未完成。

## 五分钟体验

使用 `./scripts/run dev`，打开 [本地训练页面](http://127.0.0.1:5173/training)。沿用本地虚构身份和现有数据，无需云端凭据。

1. **开始**：从首页训练舱进入，选今天或过去日期，开始空白训练。
2. **选动作**：首批六条标准动作已经产品负责人批准，也可建立本人动作。选择已有器械配置，或明确填写设备、kg/lb 和重量含义；杆重、最小增量、可用档位选填。
3. **逐组记录**：可试 `110 lb × 10`，含杆选“是”、杆重 `45 lb`。不再加一次杆重。RPE 与组类型可保持未知。保存后再记下一组；可修改、删除。
4. **恢复现场**：半填重量后进入对话壳、返回或刷新。输入与日期保留。切换三语只改变界面；个人动作原名和历史重量单位保留。
5. **结束**：暂停／继续，或取消时选择“保留已做部分并结束”。如断网，已打开页面的录组会本机暂存；结束显示“本机已结束 · 等待同步”，重连成功后进入服务端事实。完整离线重开仍属 M1.2。

已有实际组的训练不会因取消而被清空。已结束训练的最后一组不能单独删除；页面明确引导到“删除这次记录”。删除动作、组和整次训练均需确认。

## 工程变化

- 独立 `src/app/training/` 模块：页面、动作配置选择、逐组表单和展示投影分开。沿用统一草稿、队列、回执、同步和确认弹窗。
- IndexedDB 新增 `enqueueCommands`：个人动作 → 配置 → 训练动作同一次本机事务保存，并原子消耗确切草稿。后续服务端命令仍各自有真实原子回执，不宣称多请求是一个服务器事务。
- 待同步内容只覆盖本机展示，不写入正式实体缓存、不进入服务端日报。后继命令通过前一条成功回执获得版本，不猜测 revision。
- 追加迁移 `0006`（两列）与 `0007`（六条目录和18条标签）。旧迁移、历史快照、锁文件、资源标识及 M0 证据保留。旧快照缺失动作模式时读取为 unspecified，不重新分类。
- 产品负责人在任务中明确回复“批准这6条目录”。审核角色、记录时间、来源与批准范围见 [审核记录](catalog-training-first-six.md) 和 `db/catalog/training-first-six.json`。未冒充40条目录全部审核。
