# lowkkey 设计说明

> 产品原则、屏幕与视觉。接口见 `INTERFACE.md`；前端基准见 `frontend/lowkkey-frontend.html`（示例数据）。

---

## 0. 论点

**模型翻译，规则过闸，用户随时撤销。**

- 模型（Claude / GPT / 任意）负责：把自然语言、截图、语音翻译成结构化条目；在规则覆盖不到的地方提出建议。
- 规则（确定性代码）负责两件事：①所有数字结论（斜率、e1RM、下一组重量、周容量、触发器）；②**写入闸门**——判断一条输入能否直接入账（§2.1）。
- 用户负责：每天最多一个真正的决定；歧义时回答一个问题；随时撤销任何一条。

设计取舍：人工审阅是最贵的验证器。如果让用户审每一条输入，三天就会疲劳，然后开始盲签——盲签比没有审阅更糟，因为它制造了「已验证」的假象。所以验证交给便宜的确定性闸门，**只在闸门不确定时才上报给人**（选择性预测 / abstention 的结构）。外生性没有丢：闸门是代码，不是模型；模型依然不能改写或删除任何已记录的数据。

## 2. 不变量（验收红线）

| # | 不变量 | 检查方式 |
|---|---|---|
| I1 | 模型只能**提交待审提案**；用户确认后重跑闸门并原子追加事实。模型不能直接入账、撤销、删除或替用户决定。 | MCP 无直接写入、撤销、决策工具；账户与用户会话校验 |
| I2 | **日期不由模型推断。** 条目日期 = 用户文本中显式写出的日期，否则 = 用户设备本地日期（用户时区）。模型输出的日期字段一律视为建议，非今天的日期必须来自用户原话，否则触发 G2 拦截。撤销条上显示日期（仅当不是今天时）。 | 解析器单测 |
| I3 | 只追加。已提交条目永不修改或删除；撤销 = 新增一条 `revert` 条目指向原条目。 | 事实表由数据库触发器禁止 UPDATE/DELETE；状态由追加记录推导 |
| I4 | 每个派生值可追溯：`{rule_id, rule_version, input_entry_ids[], computed_at}`。UI 上点击任一 ƒ 值能看到公式和输入。 | 派生值表结构；UI 交互 |
| I5 | 原始值和原始单位永远保存。规范单位 kg，换算只做展示。 | entries.payload 同时有 `raw` 与 `kg` |
| I6 | 用户设定的约束优先于通用区间。例：「腿每周最多 1 次」→ 腿部周容量低于 10 不告警，显示为灰色。 | constraints 表 + V7 测试 |
| I7 | 歧义必问，但只问歧义那一处。同一句话中无歧义的部分照常入账。 | 解析器单测（INTERFACE.md §7 的「125那组rir0」样例） |
| I8 | **每天最多一个需要用户决定的事项**出现在「今日」。其余进「记录」页的收件箱，不推送。录入重量沿用实际记录，不按次数或 RIR 自动加减；与实际不同的已确认安排必须主动采用。 | 「今日」页决策卡数量 ≤ 1 |
| I9 | 渐进呈现：每屏 L0 = 一句结论（人话）+ 至多一个数字；L1 = 图；L2 = 公式与输入（ƒ 抽屉，默认收起）。 | 视觉走查 |
| I10 | **训练中不打断。** 专注模式期间闸门拦下的条目不弹 sheet，全部延后到「训练完成」页的「待确认」。 | 训练中页无 sheet |

### 2.1 写入闸门（确定性，代码实现）

一条输入里的每个条目依次过闸；任何一道不过 → 该条目进拦截 sheet，其余照常入账。

| 闸 | 条件（任一成立即拦截） | 拦截时问什么 |
|---|---|---|
| G1 歧义 | 解析出多个可行解（例：「125那组」匹配两组） | 「是哪一组？」列出候选 |
| G2 日期 | 日期 ≠ 今天，且不是用户原话里显式写出的（含「昨天」这类相对词，按设备时钟换算后在撤销条显示） | 「记到哪一天？」 |
| G3 覆盖 | 同日同类已有记录（例：今天已有体重） | 「替换，还是两条都留？」 |
| G4 离群 | 体重日变化 > 1.5 kg；单组 e1RM 较历史最佳 > +15%；疑似单位错（例：卧推 125 **kg**） | 「确认是 X 吗？」 |
| G5 低置信 | 模型解析片段 confidence < 0.85 | 显示模型的理解，让用户点「对」或改 |

闸门本身版本化，拦截率作为产品指标：目标 < 10% 的输入被拦截；若某一道闸长期拦截后用户都选「对」，下调它的阈值。

## 3. 屏幕规格

**导航：报头，不用 Tab 栏。** 每个浅色页顶部是同一个报头：左 `lowkkey` 字标（宋体），右日期 + 接入图标；下面一行文字导航「今日 · 体征 · 进步 · 日志」，当前页加粗并下划 2px 墨线。底部 Tab 栏取消，省下的高度还给内容。训练中页没有报头。

**版式：纸面，不用卡片。** 浅色页没有白色卡片，内容直接排在纸面上，用 1px 发丝线分节；每页开头是一句宋体「导语」（两行以内），它就是这一页的 L0。数字、短语本身可以点（体重 → 体征），不另设「查看详情」。

**输入的主次**：一键能完成的事 → 按钮；需要表达的事 → 捕获栏（只在今日）。

| # | Artboard | 关键组件 |
|---|---|---|
| 01 | 今日 | 导语「今天，肩与手臂。」；一行三个数字（今晨体重 / 近 7 天增重速度 ƒ / 周期第几周），竖发丝线分隔，数字可点；「建议」一节（宋体句 + 胶囊按钮 采用/以后，左对齐）；「训练计划」一节（右侧「5 个动作 · 16 组 · RIR 3」），动作名与重量之间用点线连接（像菜单）；「开始训练」胶囊；撤销条；捕获栏 |
| 02 | 确认 | 底部 sheet，背后是变暗的今日纸面；标签「确认」+「5 条已记录」；标题就是问题（宋体，`text-wrap: balance` 防止单字换行）；原话高亮歧义片段；三个候选按钮（推测只加虚线芯片，不预选）；查看已记录 / 跳过 |
| 03 | 训练中 | 纯黑；「‹ 今日」弱化；休息进度线；「下一组」+ 116px 重量；杠铃立面图；一行「每侧 35 + 5 · 空杆 45」；「上一组 115 × 8 · 还能 2 次」；次数步进器；还能做几次 0/1/2/3+；完成这一组 |
| 04 | 体征 | 导语是**预测**：「按当前趋势，4 月 8 日达到 75 kg。」副句「若按目标速度，这一天在 5 月中旬」；图：实测点（排便后为空心）+ 近 2 周趋势实线，今天之后变虚线延伸到 75 kg 目标线并标出日期；另一条绿色虚线是目标速度；「今天」竖虚线；「建议」一节；趋势的计算方式 / 称重条件 / 腰围 |
| 05 | 进步 | 导语即里程碑「引体向上，已能拉起自身体重。」+「加入计划」；**以体重为尺**：每个主项 = 估算 1RM ÷ 今晨体重，横条 + 一条「= 体重」竖虚线，越过这条线就是超过自重（卧推 1.25×、引体 1.02×、下拉 0.94×）；「本周练到的部位」一行文字 + 圆点；每个肌群的组数 ƒ |
| 06 | 日志 | 导语「每一条都有出处，每一条都能撤回。」；筛选 全部 / 你 / 模型 / 规则；竖向时间线，来源用**字形**而不是标签：● 你、◐ 模型、ƒ 规则、⊘ 已撤回（附原因） |
| 07 | 接入 | 导语「模型可以换，数据只有一份。」；三层（模型 → 规则 → 数据）；已接入客户端；工具权限表（工具名等宽）；端点 |
| 08 | 进入训练 · 过渡 | 见 §4.3 |
| 09 | 训练完成 | 纯黑；宋体「训练完成」；本次最重要的派生值 100px + 新纪录；每个动作最好一组；待确认 · N；回到今日 |
| 10 | 图标 | 黑色圆角方形上一大一小两枚杠铃片（暖白 = 事实，数据蓝 = 计算） |

ƒ 抽屉：点击任一 ƒ → 底部 sheet：公式（一行）、代入的数字、输入条目（可跳转）、规则版本。

## 4. 视觉系统

两种模式：日常是浅色纸面（近中性的浅灰白、宋体导语、发丝线分节，读起来像一份每天更新的简报）；训练中是纯黑（只剩数字和杠铃）。两者之间只有一次过渡：黑色按钮像一滴墨在纸上晕开（§4.3）。

**信息的四种外观**——整个设计的语法，不可混用：

| 信息类型 | 外观 |
|---|---|
| 结论（L0） | 宋体一句话，19–25px 700；配语义色圆点；最多一个数字，取整到人记得住的精度（0.86 → 0.9，201.7 → 202） |
| 事实（已记录） | 墨色，数字用 Geist 表格数字 |
| 计算（规则输出） | 数据蓝 + 斜体 *ƒ*；背景块用 data-tint |
| 模型推测（未确认） | 1px 虚线 + 紫灰；只出现在确认 sheet 与收件箱 |

**Tokens**

| card / 浮层 | #FFFFFF | #141415 |
| sunk（控件底） | #E9E9E7 | #1C1C1E |

| divider（点线、弱分隔） | #C7C7C6 | #1C1C1E |

| data-tint | #E7EDF3 | #17212B |
| 主按钮 | #141415 底 + #F7F7F5 字 | #F2F2F0 底 + #121213 字 |

颜色原则：中性色只带极轻的暖意，接近中性，不走奶油色；彩色只有一种（数据蓝），它只表示「这是算出来的」；绿/黄/红只表示状态，永远配文字。

**字体（三种，各司其职）**

| 用途 | 字体 | 规格 |
|---|---|---|
| 页面标题、结论句、问题句 | Noto Serif SC（思源宋体），回退 Songti SC | 700；标题 30/40，结论 19–25；字距 +0.3 ~ +1px |
| 所有数字 | Geist，回退 SF Pro Display | `font-variant-numeric: tabular-nums`；大数字 500 字重、负字距（116px 用 −5px） |
| 界面正文、按钮、标签 | 系统字体：SF Pro / PingFang SC | 正文 15；说明 11–13；按钮 15–17 600 |
| 代码标识（工具名、端点） | ui-monospace / SF Mono | 只在「接入」页 |

加载：`https://fonts.googleapis.com/css2?family=Geist:wght@400;500;600&family=Noto+Serif+SC:wght@600;700&display=swap`。原生 App 内置字体文件（均为 OFL 许可）。

- 间距刻度：6 / 10 / 14 / 20 / 28 / 38；页面左右 16；卡片内边 16–18；卡片间距 12。
- 圆角：卡片 18、按钮 12–16、芯片 10–15、胶囊 26。
- 触控目标 ≥ 44px。图标：1.6px 描边线性图标，不用 emoji。
- 学术细节（OLS、Epley、肌群权重、RIR）只出现在 ƒ 抽屉，不出现在 L0/L1。

### 4.1 文案

参照 Apple 的界面文案：平静、准确、像一个懂行的人在跟你说话。不卖萌，也不像机器。

- **导语是一句陈述，带句号。** 「今天，肩与手臂。」「按当前趋势，4 月 8 日达到 75 kg。」「引体向上，已超过自身体重。」
- **说明用完整句，称「你」。** 「有两组 125 lb。你写的是……」系统不自称「我」，不说「抱歉」「没听懂」。
- **专业术语照常用**：RIR、e1RM、组、次数、kcal。它们是这个领域的通用语言，面向会练的人。首次出现可附一句解释（「RIR · 还能再做几次」），之后直接用。
- **按钮用 iOS 惯用词**：采用 / 以后、完成、撤销、跳过、开始训练、完成本组。
- **标签用名词**：建议、需要确认、训练计划、相对力量、本周训练部位。
- **数字先于形容词**：写「+1.9 kg/周」，不写「长得很快」；需要判断时用中性的比较：「高于 0.3 kg 的目标」。
- **庆祝克制**：「新纪录」「较之前 +5%」。不用感叹号、emoji、「哦/呢/吧」。
- **模型的猜测只挂「推测」芯片**，不预选，不劝说。
- 规格里的工程词（闸门、入账、拦截）不上界面；界面上说「记录」「需要确认」「撤销」。

### 4.2 杠铃立面图

训练中页的杠铃是一张克制的工程立面图，不是插画：
- 杠身 2.5px 实线；套筒用 1.25px 描边空心矩形；卡箍为实心小块；杠身中段有极细的滚花刻线。
- 杠铃片为实心圆角矩形，**高度按真实直径比例**（以 45 lb 为 88px：35 lb ≈ 73，25 lb ≈ 60，10 lb ≈ 45，5 lb ≈ 40，2.5 lb ≈ 32），**明度按重量**：越重越亮（35/45 #EAE7E0，25 #ABA8A1，10/5 #807D76，2.5 #57554F）。
- 两侧对称绘制，从卡箍向外排列；图上不写字，图下一行说明「每侧 35 + 5 · 空杆 45」。
- kg 片同理（20 kg 为最大高度）。只用于杠铃类动作；哑铃、器械不画图，只显示数字。

### 4.3 动效与触感

进入训练（今日 → 训练中），620 ms，cubic-bezier(0.32, 0.72, 0, 1)：
- 0 ms：按钮缩到 0.97，轻触感。
- 0–380 ms：黑色按钮就是墨滴，以按下点为圆心做 clip-path 圆形扩散；同时浅色层 scale 1 → 0.92、opacity 1 → 0.35、blur 0 → 3 px。
- 380 ms：状态栏切浅色字。
- 380–620 ms：重量数字 translateY 12 → 0、opacity 0 → 1，杠铃晚 80 ms 淡入；620 ms 重触感。
- 结束训练：逆放 480 ms，黑色收回「今日」的训练卡，卡片显示「已完成」。
- 尊重「减弱动态效果」：退化为 200 ms 交叉淡入。

触感只用四种：记录 = 一次轻触；休息结束 = 两次短震；新纪录 = 成功反馈；需要确认 = 无（从不用震动表达错误）。

## 5. 路线

- v1：手机 9 屏 + 进入训练过渡 + MCP。
- 暂缓：锁屏实时活动 / 灵动岛（ActivityKit，两者是同一套实现，一起做）、Apple Watch。等 v1 的数据和闸门稳定后再评估。
- 之后：语音一句话记组：「一百二十五，七个，力竭」→ 规则解析 → 把关。


## 2026-09-30 微观体验补充

原始前端 HTML 文件保留。运行时空状态改用主动邀请；手机按可用宽度排版，保持字号与触控区域。首页首入 280ms / 4px 渐入；Sheet 320ms 指定曲线，真实背景同步缩至 0.96。减弱动态效果取消缩放与位移。

录入参考：重量始终可编辑，实际预填本场同组别上一组、最近历史或已确认安排；主动清空后必须填写。不同的安排重量单独点击采用，次数与 RIR 不触发自动加减。服务器确认后显示成功。宏观单点裁决：首页每当地日期最多一项主动建议，计划、周期和饮食修改必须由用户采用；关闭、到期、离线、“以后”均不执行。首次设置不强制目标；增肌、减脂、维持和只记录共用原有 Sheet 控件。
