# M1.6 第一批：饮食便签

2026-09-18：本文件替代旧的“整餐长表单＋手动保存”实施稿。产品负责人选择先记吃了什么；自由文字直接成为正式记录，营养全未知也可保存。

本批实现与验收见 [饮食便签交付](M1-diet-notes.md)。训练六动作目录已获批准，按天训练交互也已获准继续，不再次等待旧审批。

- /nutrition?date=…：一条原文、一条记录，离开整条编辑区自动保存。营养、餐别与时间按需展开。
- Meal 增加可空 note 快照，与 items 互斥；原文字数上限2000，未知营养保持null，无便签到期机制。
- 按日 nutritionContentRevision 与领域写入同事务推进。记全请求绑定所见内容版本及声明版本，不能重连后静默改绑。
- 旧明细与旧候选保留。纯文字候选可明确转为正式便签，draftRef消费与新记录同事务，不自动批量迁移。
- 队列接入 meal.* 和 day-claim.*；同一记录的连续编辑通过本人回执串联版本。
- 标签基准换算、受审参考食物、份量及配方转入后续可选复用批次，完整M1要求不删减。

## 已修复的历史并发缺口

旧设备在 unreviewed/partial 状态看到1餐，另一台设备新增第2餐后，旧声明revision曾不足以验证“用户看过的内容”。旧证据保留在 `.artifacts/m1-manual-diet-preflight/day-content-review.json`。

本批对每次饮食内容变化推进独立内容版本，即使完整度尚未确认也推进；即使传入当前声明revision，旧内容版本也被拒绝。对应真实D1用例在 `tests/diet-notes.test.ts`，最终结果以本批验收报告为准。
