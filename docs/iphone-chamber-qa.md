# iPhone 状态舱修复验收 · 2026-10-06

> 历史验收记录：以下结论对应各批次当时的代码与检查结果。当前发布状态、未解决问题及复测要求以 [公网预览验收](public-preview-checklist.md) 为准。旧诊断入口的说明仅供追溯；本轮源码已移除该功能。

## 本次改动

- 根页面、外壳和浏览器主题色同步切换；页面安全区的背景不依赖退场动画。登录失效后恢复浅色页面。
- 固定文档滚动，只给外壳应用一次可视视口偏移。首页输入保留上方内容；训练页使用完整的独立滚动区，键盘和短屏不会把输入或提交控件挤成零高度。
- 填入重量即可提交，按钮准确展示将保存的重量、单位、次数。单位可切换，手输数字不换算；推荐值换算至两位小数，显示值与提交值一致。本场同动作保留单位选择。
- 原杠铃 SVG 在首次无重量时保留中性轮廓，输入后显示实际配片；配片节点稳定更新，新增杠片淡入 160ms。哑铃／器械／辅助动作使用相应重量说明。
- 本场动作和组次优先读取开始时的快照；其他设备修改或删除每周安排不影响正在训练的动作清单。进度线表示已完成正式组数。
- 非单位类异常仍须核对；训练中延期至完成页，不把待确认组显示为已完成，也不重复提交同一待确认组。

原交接 HTML、业务规则、公共接口、数据库和认证模式均未修改。测试记录仅写入隔离 D1。

## 自动化与局限

本轮全仓类型检查、ESLint、构建通过；52 项规则/API/账户测试、82 项 Chromium/WebKit 测试及本地 OAuth/MCP 端到端通过。增加顶栏可见性与长数字裁切断言后，专项键盘测试在两个引擎再次通过。

Chromium 和 WebKit 检查首次重量、小数／无效输入、单位切换、推荐值覆盖、SSE、丢失响应后幂等重试、计划快照、真实组数进度、深浅页面切换、抽屉与减弱动态效果。

模拟 visualViewport 的高度与 offsetTop，验证键盘尺寸下内容可达、输入保留和文档不滚动。十屏截图使用隔离账户，另有 393 × 852、模拟 59/34px 安全区的训练截图。这些测试不能模拟 iPhone 系统状态栏和真实软键盘，不能据此宣称真机通过。

背景处理依据：[WebKit 的安全区说明](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)。本次未归因于某个 iOS 系统缺陷；是否仍有系统层残留须由真机复测确定。

## 请在你的设备完成这四项

设备：iPhone 15 Pro，iOS 26.6.2。**添加到主屏幕模式为主，Safari 再重复一遍**。先退出并重新打开网页，核对 `/healthz` 的 version 与发布提交一致。

1. **顶部颜色**：今日 → 开始或继续训练 → 今日 → 日志，快速往返 5 次；训练黑色、其他页面浅色，稳定后顶部不能残留上一页颜色。训练中切到其他 App 再回来，旋转屏幕后再复测。
2. **首次重量与器械**：在真实训练中，未填重量仍看到杠铃轮廓；输入实际重量后应看到配片。切换 kg/lb，手输数字不变，按钮同步显示单位。点击明确的“记录 … × …”，只写入一组。哑铃显示单只重量说明，不显示杠铃配片。
3. **键盘**：首页输入中文，键盘上方仍应看见首页内容和输入框。收起键盘不留空白；训练重量输入时，动作、单位可见，保存按钮可以滚动到达。不要为测试向个人账本写入虚构数据。
4. **完整流程**：记录一组 → 切动作／额外加组 → 中途或正常结束 → 完成页 → 日志撤销错误记录；检查图表和状态刷新。异常重量待核对时，从完成页进入确认，不应悄悄入账。

结果记录：模式、操作步骤、实际结果、提交 version；有问题附从操作前开始的录屏。**当前真机验收：待用户复测。**
