# lowkkey v6 · AI 原生状态舱（规划草案）

状态：方向已于 2026-10-21 确认，Phase 0 动工。决定如下：

- 首页改为 AI 布置的 board：**确认**。
- 信号：**收窄**。不给人「今天累 / 状态好」这类选择，减少决策带宽；这些话在对话里自然会说。舱里只保留一扇门：带着当前上下文回到对话（不写入任何事实）。
- 印章：方向**待看成品**。此前「简体字 + 日历」的样子没有设计可言；里程碑的载体必须先在样板页里做出来、看过再定，不能走印章刻字的俗套。
- Web Push：**做**。
- 范围：**不只是健身，而是整个身体、作息、休息与日常**。v6 的面板即为 training / body / rhythm（作息与休息）/ notes，不再把「日常」留到 v7。
- 工程：**先清理，从干净的代码开始**。审美体系与美学建设是最重要的事；风格标的取 Cartier（精确、克制、一种签名色、发丝线与雕刻感的数字）与 Hermès（工艺、材质、留白、一点幽默），叠在水墨 / 鎏金 / 珍珠的材质语言之上。

## 0. 一句话定位

lowkkey 是一块由 AI 维护、人只看不填的「状态舱」。对话发生在 Claude / ChatGPT；事实、安排、信件和布置，由 AI 写进舱里；人打开舱，看到自己被理解的样子。

这个定位已经确定。v6 要回答的是：**舱本身应该长什么样、怎么互动、凭什么让人喜欢**。

## 1. 现状诊断（为什么值得做一次大版本）

v5 把「AI 写、网页看」跑通了，v5.1（本周）补上了管理者手册、guide、环境光、心跳、按压和下拉。但有五个结构性的天花板：

1. **页面按内容类型组织**（next / recap / body / log / notes），不是按「我现在在哪」组织。打开舱的第一眼是一张计划表，而不是一个状态。
2. **AI 只能写内容，不能布置舱**。它能写周信、批注、选主题，但不能决定首页先给你看什么。展板的灵魂是「布置」，现在缺这一半。
3. **人与舱之间没有回路**。不填表是对的，但连一次轻触都没有：练完了、今天很累、想聊聊，这些最该流回 AI 的信号，现在只能靠人再去打字。
4. **没有「物」**。里程碑只是一行 week_facts，没有可以收藏、可以回看、可以分享的东西。趣味性无处安放。
5. **工程密度**。2.5k 行里大量上千字符的单行，CSS 一整块 480 行，客户端打包了 zod 校验，没有离线缓存。能跑，但不优雅，也不利于再往上盖楼。

## 2. 核心主张：四根柱子

### 2.1 板（Board）：AI 布置的首页

首页不再是 next，而是 **board**：一叠卡片，由 AI 通过 `curate.board` 决定本周放哪些、什么顺序、配一句话。卡片来自固定目录（AI 只能挑选和排序，不能造新卡）：

| 卡       | 内容                                              | 数据来源               |
| -------- | ------------------------------------------------- | ---------------------- |
| presence | AI 的一句当下话（「昨天的卧推记下了，今天歇着」） | curate.board.line      |
| next     | 下一次训练，主卡；点开进入完整计划页              | set_plan + curate.next |
| week     | 本周完成 / 计划，圆环或七格                       | weekStatus             |
| weight   | 最新体重 + 七日迷你线                             | log_weight             |
| letter   | 最近一封周信的首段，点开读全文                    | curate.recap           |
| seal     | 本周获得的印章                                    | 由事实派生             |
| focus    | 焦点主项的小曲线                                  | strengthSeries         |
| rest     | 休息日专用：恢复、睡眠、AI 的一句话               | curate.board           |

没有 AI 布置时有默认顺序；AI 每周整理一次板面成为日常例程的一部分（写进管理者手册与 guide.missing）。

标签改为 `board · recap · body · log · notes`，next 的完整计划作为 board 主卡的「展开」，用 View Transitions 做共享元素过渡：卡片长成一页，而不是切换标签。

### 2.2 门（Door）：回到对话的一扇门，不是信号

舱不向人索取任何判断。原先设想的「练完了 / 今天累 / 状态好」被否决：那是把决策带宽推给人，而且这些话在对话里自然会说出来。

保留的只有一扇门：每张卡右下角一个极轻的入口，带着这张卡的上下文打开宿主 AI，并预填一句开场白（「我们聊聊明天的腿与肩」「这周的信我读了，想说……」）。门不写入任何事实，只是把人送回对话。回路由 AI 在对话里完成，舱保持安静。

### 2.3 成就（Medals）：由 AI 授予，有名字，有故事

决定（2026-10-21）：奖章不是固定目录，而是 AI 写入的。形式是圆形奖章（金属圈、分钟刻度、一个图样、名字在下），内容三样：

- **名字**由 AI 起，雅一点，二到八个字，不用「第一次」「成就」这类说明文字。
- **图样**只有一个：数字是重点时用数字，否则一个字。
- **故事**一到三段很短的小故事，题材随意——一个片段、一段小说、她和他、一个清晨——不必和训练有关，但要配得上这个时刻。

授予的时机来自真实的事（纪录、门槛、突破、连续、第一封信、艰难的一周），一周最多一两枚；`guide.missing` 在有这样的事而没有章时提醒。也可以和用户约定一枚尚未达成的（date 为 null），达成时补上日期、写故事。成就墙在 recap 页末尾，本周新得的会出现在 board。

### 2.4 质感（Feel）：让 Web 摸起来像原生

- **共享元素过渡**：View Transitions API（Safari 18 / Chrome 已支持）做卡片到页面的生长；不支持时退回淡入。
- **弹簧曲线**：`linear()` 时间函数生成真实弹簧，替换现在的 cubic-bezier；按压、抽屉、下拉统一一套物理。
- **即开**：Service Worker 缓存上一次的 state，打开舱 0 等待，再后台同步；心跳在同步时加快已经有了。
- **信到了**：Web Push（iOS 16.4+ 主屏幕应用支持）。AI 写周信、落新印章时服务端推一条；一周最多两三条，可关。舱在合上时也有生命。
- **时辰**：天光随一天的时刻有极轻的冷暖变化，叠在周主题之上。
- **主屏幕**：恢复一次性的、有礼貌的「添加到主屏幕」提示，只在第二次打开时出现一次。

## 3. 范围：整个身体、作息、休息与日常，但不做记录器

已定：lowkkey 不只是健身，而是一个人的身体与日常节律。但**我们不做睡眠记录**：每天记睡眠是 Apple 健康的工作，让人或 AI 去记是对决策带宽的消耗，也做不好。

所以 rhythm（作息与休息）面板的内容只来自对话里自然出现的事实，由 AI 写入：

- **休息**：休息日是一等公民。AI 可以在 `curate.board` 的 rest 卡写当天的安排与恢复提示；连续训练与休息的节律由代码从记录派生（已有 contact sheet 与 week）。
- **日常背景**：考试周、出差、搬家、睡得差——用户在对话里提到的、带日期的短期背景，已有 `training_context`；v6 把它做成有日期的条目（`log_context({date, until?, text})`），board 与计划都能引用，到期自动淡出。
- **睡眠（可选、以后）**：若要接，用 iOS 快捷指令把 Apple 健康的睡眠样本定时推到 `/v1/health`，人不记录，AI 只读。不在 v6 范围内。

原则不变：形式通用，价值来自领域深度。架构按面板归组（schema、派生、视图、工具），只做约定不做插件系统。

## 4. 协议 v6（AI 侧）

- `curate.board`：`{line?, cards?:[{kind, note?}], week}`，省略保留、null 清空；服务端校验 kind 在目录内。
- `log_context`：有日期的日常背景条目，`contexts(owner,date,until,text)`；`get_brief.contexts` 返回仍有效的条目，到期不再返回。首页状态行下显示。已落地（2026-10-21，迁移 0006_contexts）。
- `award`：AI 授予奖章，`medals(owner_id,key)` 表，同 key 覆盖；`delete({kind:'medal',key})`。`get_brief.medals` 原样返回。
- `guide` 成为唯一的引导对象，`onboarding.next_step` 退役；`missing` 新增 `board`。
- prompts 增加「整理板面」；管理者手册增加「先回应信号」「每周布置板面」两条例程。
- 协议版本 6.0.0（已切换），迁移 0005_medals、0006_contexts、0007_push。

## 5. 工程清洗（Phase 0，行为不变）

1. **格式**：引入 Prettier（printWidth 120）+ ESLint 规则，一次纯格式化提交，测试护航；之后代码审查才有可读性。
2. **目录**：`src/app/{shell, board, plan, recap, body, log, notes, ui, motion, data}`；`ui` 收纳 Voice、Card、Section、Stat、Chip、Sheet 等基础件；页面不再各自手写同样的 header/empty。
3. **CSS 分层**：`tokens.css`（颜色、间距、字号、圆角、阴影）/ `base.css` / `components.css` / `pages/*.css` / `motion.css`；清掉 `.tnote`、`:active` 残留、重复的 `[hidden]` 等。
4. **客户端瘦身**：前端不再 `parse` zod schema（只用类型），zod 留在协议包与服务端；预计 JS 包减三成。
5. **动效归一**：`motion/` 一处定义弹簧与时长，页面只调用。
6. **服务端**：store.ts 拆成 facts / curation / clients；brief 组装独立；保持 D1 原子批次不变。
7. **测试**：core 单测补齐派生（seals、weekStatus 已有）；e2e 按页分文件；增加一组「视觉基线」截图（三主题 × 深浅 × 三宽度）作为回归对比。
8. **文档**：INTERFACE / DESIGN 按面板重写；handoff 目录只留当前真相。

## 7. 审美体系：风格标的与取法

- **Cartier**：一种签名色（红）用得极少、极准；发丝线边框；雕刻感的数字与罗马数字；黑白与留白；一切都「精确」。取法：签名色纪律、发丝线、数字作为主角、克制。
- **Hermès**：橙色作为识别而非装饰；工艺与材质（皮革、丝绸、马鞍线）；橱窗里的幽默与轻盈；纸感。取法：材质语言（纸、墨、金箔、珍珠母）、细节里的一点幽默（心跳的句点、信的署名）、留白是奢侈。
- **我们自己的根**：水墨的黑白灰、鎏金的暖、珍珠的冷光；中文宋体正文；小写英文标签。v6 不换根，只把它做成一个有纪律的系统：字号阶梯、间距阶梯、三种发丝线、两种阴影、一套弹簧。

已定的细则（2026-10-21）：

- 基础数字全部用 Inter，清楚为先；Bodoni Moda 只给少数有纪念意义的数字：奖章上的数字、信末的日期。品牌字定为 Bodoni Moda 正体（500，低光学尺寸），与奖章上的数字同一张脸；全站字体链接已加载。
- **只有两套主题，各有含义。** 水墨吸收了珍珠：冷白的纸、银灰的线与渐变、石板灰蓝的签名色、天光里极淡的珍珠母虹彩；它是日常，默认如此。鎏金留给值得庆祝的一周：纪录、里程碑、连续完成。珍珠作为独立主题退役，历史数据里的 pearl 读作水墨。
- 成就是奖章，不是刻字板（见 2.3）。

样板页（`/__preview/styleguide`，仅开发环境）是这个系统的活文档。先在样板页里成立，再铺到应用。

## 8. 不做的事

- 不做聊天界面：对话永远留在宿主 AI。
- 不做表单、设置项、配色选择器：舱的变化只来自 AI 和事实。
- 不做通知轰炸：推送只在有信、有印章时。
- 不做通用展板引擎：面板化只是约定。
- 不做游戏化积分：印章来自真实事实，没有分数和排行。
